= Handling Code Duplication in Vertical Slice Architecture
:toc:
:toclevels: 3

== 1. Core Principle

Prefer *duplication over wrong abstraction*.

Why:

* Each slice represents an independent use case.
* Over-abstraction introduces coupling between slices.
* Premature reuse leads to god services and hidden dependencies.

== 2. Types of Duplication

=== 2.1 Harmless Duplication: Keep It

[source,csharp]
----
public record Response(Guid Id, string Name);
public record Response(Guid Id, string Name);
----

DTO duplication is acceptable because DTOs are use-case specific.

Rule: Duplicate DTOs freely.

=== 2.2 Behavioral Duplication: Extract Carefully

[source,csharp]
----
var total = salary - CalculateBenefits(employee);
----

When the same calculation appears in multiple slices, extract the business rule into the domain.

[source,csharp]
----
public static class BenefitsCalculator
{
    public static decimal Calculate(Employee employee)
    {
        // business rule here
    }
}
----

Rule: If logic represents a business rule, move it to the Domain.

=== 2.3 Infrastructure Duplication: Extract Early

[source,csharp]
----
await dbContext.Employees
    .Where(employee => employee.IsActive)
    .ToListAsync(cancellationToken);
----

Repeated query patterns can be extracted.

[source,csharp]
----
public static IQueryable<Employee> WithDependents(
    this IQueryable<Employee> query)
{
    return query.Include(employee => employee.Dependents);
}
----

Rule: If duplication is a data access pattern, extract it to Infrastructure.

== 3. What Should Be Shared

=== 3.1 Domain

[source,text]
----
Domain/
|-- Employee.cs
|-- Dependent.cs
`-- Policies/
    `-- BenefitsPolicy.cs
----

Share:

* Business rules
* Invariants
* Calculations

=== 3.2 Infrastructure

[source,text]
----
Infrastructure/
|-- Persistence/
|   |-- AppDbContext.cs
|   `-- Queries/
|       `-- EmployeeQueries.cs
`-- ExternalServices/
    `-- WarehouseClient.cs
----

Share:

* EF Core query helpers
* External API clients
* Caching logic
* Technical adapters

== 4. What Should Not Be Shared

=== 4.1 Application Services

[source,csharp]
----
EmployeeService.GetEmployee();
----

Avoid this because it usually becomes a god object and couples many slices together.

=== 4.2 Shared DTOs

[source,csharp]
----
Shared/EmployeeDto.cs
----

Avoid shared DTOs unless the contract is intentionally shared and stable.

=== 4.3 Generic Repositories

[source,csharp]
----
IRepository<T>
----

Avoid generic repositories when EF Core already provides useful query and change-tracking behavior.

== 5. Practical Heuristics

Extract only when all are true:

. Used in three or more slices.
. Logic is identical.
. It represents a stable concept.

== 6. Patterns for Safe Reuse

=== 6.1 Domain Policy

[source,csharp]
----
public class PaycheckPolicy
{
    public Money Calculate(Employee employee)
    {
        // pure business calculation
    }
}
----

=== 6.2 Query Object

[source,csharp]
----
public static class EmployeeQueries
{
    public static IQueryable<Employee> Active(
        this IQueryable<Employee> query)
    {
        return query.Where(employee => employee.IsActive);
    }
}
----

=== 6.3 Feature-Local Helper

[source,csharp]
----
internal static class Mapping
{
    public static Response ToResponse(Employee employee)
    {
        return new Response(employee.Id, employee.Name);
    }
}
----

Keep helpers local to the slice until reuse is proven.

== 7. Trade-offs

[cols="1,2",options="header"]
|===
| Scenario
| Action

| Same DTO shape
| Duplicate

| Same business rule
| Move to Domain

| Same EF query
| Extract helper or query object

| Same orchestration
| Keep duplicated

| Uncertain reuse
| Wait
|===

== 8. Mental Model

[source,text]
----
Vertical Slice  = Use Case
Domain          = Truth
Infrastructure  = Plumbing
----

Slices may duplicate flow and DTO shape, but business truth should live in the domain.

== 9. Final Rule

Share *rules*, not *flows*.
